인자: {"query": "", "top_k": 5}
반환 근거: (도구가 검색을 실행하지 않고 스키마 검증 단계에서 즉시 오류 반환)
실제 서버 응답 원문:
  {"error":"invalid_query","message":"query는 1~300자여야 합니다."}
최종 답: (해당 없음 — 오류 단계에서 답변 생성 전 중단)
중단·이관 이유: query 길이가 인자 스키마(1~300자)를 벗어나 즉시 거절. 재시도하지 않고 사용자에게
  질문을 다시 입력해 달라고 요청해야 한다.
관찰:
  - 프런트엔드(static/app.js)는 이미 빈 입력일 때 전송 자체를 막고 있어(`if (!q) return;`) 이 오류가
    실제 UI에서 발생할 일은 거의 없다. 그래도 서버가 동일한 규칙을 한 번 더 검증하는 것은 프런트엔드를
    거치지 않는 직접 API 호출(예: 이 트레이스처럼 curl로 재현한 경우)에 대한 방어선으로 유효하다.
