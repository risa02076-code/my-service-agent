# 도구 정의서 — OO제약사 사규 안내 챗봇

이 챗봇이 호출할 수 있는 도구는 4개다. 셋은 읽기 전용이고, 실제로 상태를 바꾸는 "쓰기" 도구는 `log_feedback` 하나뿐이다 — 이 챗봇은 사규 원문을 그대로 찾아 보여주는 안내용이지, 예약을 확정하거나 규정을 수정하거나 개인정보를 열람하는 서비스가 아니기 때문이다. 그런 요청은 도구를 만드는 대신 전부 `escalate_to_department`로 이관되도록 설계했다.

---

## 1. search_regulation (읽기)

| 항목 | 내용 |
|---|---|
| 이름 / 한 문장 | `search_regulation` — 사용자 질문과 관련된 사규 조항을 하이브리드 검색(코사인+BM25)으로 상위 k개 찾아 반환한다 |
| 쓰는 때 | 규정·절차·기준(휴가, 경조금, 징계, 출장비 등)에 대한 자연어 질문일 때 |
| 안 쓰는 때 | 사용자가 규정명+조 번호를 이미 정확히 지목했을 때(→ `get_regulation_article`), 개인 인사정보 조회, 규정과 무관한 잡담 |
| 인자 스키마 | `query`: 문자열, 필수, 1~300자 · `top_k`: 정수, 선택, 3~10(기본 5) · `regulation_filter`: 문자열, 선택, 47개 규정명 enum 중 하나만 허용(자유 문자열 금지). 누락값(`query` 없음/공백)은 즉시 오류 |
| 반환 형식 | 배열, 각 항목 `{id, regulation, article, page, url, text, score}`. 오류 코드: `invalid_query`, `invalid_regulation_filter` |
| 실패 뒤 행동 | 전체 결과 `score < 0.35` → 재검색하지 않고 근거 없음 응답으로 전환 · `invalid_regulation_filter` → 재호출 대신 규정명 후보 목록을 사용자에게 되묻는다 · 검색 서버 연결 실패 → 1회만 재시도, 실패 시 중단(동일 호출 반복 금지) |

## 2. get_regulation_article (읽기)

| 항목 | 내용 |
|---|---|
| 이름 / 한 문장 | `get_regulation_article` — 규정명과 조 번호가 이미 확정된 경우, 검색을 거치지 않고 해당 조의 전체 원문을 그대로 가져온다 |
| 쓰는 때 | 사용자가 "취업규칙 제27조 보여줘"처럼 정확히 지목했을 때, 또는 출처 칩을 눌러 원문을 다시 확인할 때 |
| 안 쓰는 때 | 조 번호가 불확실하거나 여러 조에 걸친 비교·탐색이 필요할 때(→ `search_regulation`) |
| 인자 스키마 | `regulation`: 문자열, 필수, 47개 규정명 enum 중 하나 · `article`: 문자열, 필수, 정확한 조 라벨(예: "제27조")만 허용, 부분 일치·유사어 매칭 금지 |
| 반환 형식 | 단일 객체 `{regulation, article, chapter, page, url, text}`. 오류 코드: `not_found` |
| 실패 뒤 행동 | `not_found` → 존재하지 않는 조를 추측해서 보여주지 않고, 정확한 조 번호를 다시 확인해 달라고 되묻는다 (자동으로 `search_regulation`에 위임하지 않음 — 사용자가 착각한 조 번호일 수 있으므로) |

## 3. escalate_to_department (이관 — 상태 변경 없음)

| 항목 | 내용 |
|---|---|
| 이름 / 한 문장 | `escalate_to_department` — 챗봇이 답할 수 없는 범위의 질문을 정해진 담당 부서 안내 문구로 변환한다 |
| 쓰는 때 | 개인 인사정보(연봉·인사고과·잔여휴가 등) 질문, 규정의 최종 해석·예외 승인이 필요한 질문, `search_regulation`이 근거를 못 찾은 질문, 규정 변경/승인처럼 애초에 이 챗봇에 없는 기능을 요청하는 경우 |
| 안 쓰는 때 | 사규 원문 인용만으로 답변 가능한 일반 질문 |
| 인자 스키마 | `reason`: enum(`personal_data` \| `needs_legal_judgment` \| `no_evidence` \| `unsupported_action`), 필수 · `topic_hint`: 문자열, 선택(로그용, 답변에는 노출하지 않음) |
| 반환 형식 | `{department, message}` — `department`는 사전 정의 목록(인사총무부/컴플라이언스팀/IT보안팀 등)에서만 선택, 챗봇이 임의로 부서명을 지어내지 않는다 |
| 실패 뒤 행동 | `reason`이 목록에 없는 값이면 기본값 "인사총무부"로 안내하고, 그 사실을 서버 로그에 남겨 사람이 나중에 reason 목록을 보완할지 검토한다 (사용자에게는 오류를 노출하지 않음) |

## 4. log_feedback (쓰기 — 유일한 상태 변경 도구)

| 항목 | 내용 |
|---|---|
| 이름 / 한 문장 | `log_feedback` — 사용자가 누른 👍/👎 평가를 로컬 피드백 로그에 추가(append-only)한다 |
| 쓰는 때 | 답변이 완료된 뒤 사용자가 명시적으로 버튼을 눌렀을 때만 |
| 안 쓰는 때 | 모델이 스스로 판단해서 자동으로 남기는 경우 — 사람의 명시적 클릭 없이는 절대 호출하지 않는다 |
| 인자 스키마 | `vote`: enum(`up`\|`down`), 필수 · `question`, `answer`: 문자열, 필수 · `comment`: 문자열, 선택, 최대 500자 |
| 반환 형식 | `{ok: true}`만 반환 — 저장 경로·파일 형식 등 구현 세부는 노출하지 않는다 |
| 실패 뒤 행동 | 저장 실패 시 1회 재시도, 그래도 실패하면 사용자에게는 알리지 않고 조용히 무시한다(피드백 저장 실패가 챗봇의 정상 응답을 막아서는 안 됨). 단, 서버 로그에는 실패를 남긴다 |
